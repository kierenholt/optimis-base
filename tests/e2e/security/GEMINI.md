# Security, Compliance & Administration E2E Verification Suites (`tests/e2e/security`)

This directory contains sequential Playwright E2E integration suites for session authentication, persona resolution, DSL safeguarding vault envelope encryption, UK GDPR Subject Access Requests (SAR) & retention purge, PII-scrubbed diagnostic bundle export, terminal break-glass CLI, and external sync/KMS dependency flags.

---

## E2E Spec Files

* [`backend_session_persona_resolution.spec.ts`](file:///home/kieren/Documents/code/optimis/tests/e2e/security/backend_session_persona_resolution.spec.ts):
  * Verifies `GET /api/auth/personas`, `POST /api/auth/persona` (`SameSite=Strict` `mis_session` cookie issuance), and `GET /api/auth/session` against seeded `ADMIN`, `DSL`, `TEACHER`, and terminated staff in `core.db`.
  * Verifies that switching to a persona without required endpoint scopes causes `POST /api/p/:plug_id/rpc/:method` to fail fast (`caller lacks required DAL scopes`).
  * Verifies that setting `ENABLE_DEV_PERSONA_SWITCHER=false` fails fast with `REAL_SSO_NOT_CONFIGURED` when loading real SSO (`/api/auth/sso/login`) and blocks dev persona endpoints with `403 DEV_PERSONA_SWITCHER_DISABLED`.
* [`safeguarding_vault_dsl_unlock.spec.ts`](file:///home/kieren/Documents/code/optimis/tests/e2e/security/safeguarding_vault_dsl_unlock.spec.ts):
  * Verifies Section 5B Safeguarding Isolation: write-only postbox creation by Teachers (`dal.safeguarding.create`), 403 rejection of non-DSLs on vault read/key-renewal/decrypt, envelope-encrypted DSL Vault UI unlock via short-lived signed OAuth Cloud Key (`POST /api/safeguarding/cloud-key/renew` & `POST /api/safeguarding/notes/:id/decrypt`), and strict write-only Lua sandbox isolation.
* [`gdpr_sar_redaction_and_purge.spec.ts`](file:///home/kieren/Documents/code/optimis/tests/e2e/security/gdpr_sar_redaction_and_purge.spec.ts):
  * Verifies UK GDPR Subject Access Request (SAR) aggregation across `core.db` and attached `plugin_<name>.db` instances (both `ACTIVE` and `UNINSTALLED_DORMANT`), interactive redaction of `redactable_fields` in the React Host Shell Admin SAR Redaction UI, KCSIE safeguarding retention lock protection (`KCSIE_RETENTION_LOCK`), and zero-orphan statutory retention purges.
* [`admin_diagnostic_bundle_export.spec.ts`](file:///home/kieren/Documents/code/optimis/tests/e2e/security/admin_diagnostic_bundle_export.spec.ts):
  * Verifies Section 8 Gap 1, Section 9.3 & Section 10.3 Admin-Exported PII-Scrubbed Diagnostic Bundle (`GET /api/admin/diagnostics/bundle` & "Download Plugin Diagnostic Bundle" control in the Host UI Shell): RBAC enforcement rejecting non-Admin/DPO personas (`403 UNAUTHORIZED_ADMIN_DIAGNOSTICS_SCOPE`), Lua stack trace extraction (`file`, `line`, `method`, `error_class`), execution and SQLite write lock wait/hold durations (`duration_ms`, `sqlite_lock_wait_ms`, `sqlite_write_hold_ms`), strict stripping of pupil IDs, UPNs, ULNs, RPC request payloads, and local variables across JSON and `.log` exports, and bounded ring-buffer FIFO eviction.
* [`break_glass_config_cli.spec.ts`](file:///home/kieren/Documents/code/optimis/tests/e2e/security/break_glass_config_cli.spec.ts):
  * Verifies Section 7C Local Break-Glass CLI (`./bin/mis-server config list`, `config get <key>`, `config set <key> <value>`, and `config repair-sso`): inspecting and mutating `__system_config` in `core.db` from the terminal (with updated `school_name` immediately reflected in the React Host UI Shell `host-school-name`), repairing misconfigured SSO settings (`sso_oidc_issuer_url`, `sso_oidc_client_id`, `sso_provider`, `sso_redirect_uri`) when `ENABLE_DEV_PERSONA_SWITCHER=false` to unblock `POST /api/test/auth-mode` and `GET /api/auth/sso/login`, and fail-fast non-zero exit code validation on missing/invalid CLI arguments.
* [`external_sync_and_kms_flags.spec.ts`](file:///home/kieren/Documents/code/optimis/tests/e2e/security/external_sync_and_kms_flags.spec.ts):
  * Verifies environment feature flags and mock services for the three external dependencies (`ENABLE_REAL_CLOUD_KMS`, `ENABLE_REAL_PARENT_DMZ_SYNC`, `ENABLE_REAL_MAT_SYNC` via `POST /api/test/external-deps-mode`): fail-fast `503` rejection (`REAL_CLOUD_KMS_NOT_CONFIGURED`, `REAL_PARENT_DMZ_NOT_CONFIGURED`, `REAL_MAT_SYNC_NOT_CONFIGURED`) when switched to real mode without provider configuration in `__system_config`, Public Cloud DMZ Parent Container sanitized read-projection push & write-inbox pull enforcing guardian PR & court-order blocks (`REJECTED_SAFEGUARDING_BLOCK`), and MAT Central Sync policy pull & PII-free school-level analytics push.
